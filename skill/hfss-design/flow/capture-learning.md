# 流程:开工先读、收工先记(经验库与卡片库)

> `knowledge/` 记**经验**(类级机理与坑,不记数据),`design/` 记**数据**(闭式公式 / λ 归一化尺寸 / 报告性能)。

## 开工先读
1. 认出这次是哪类天线(贴片 / 磁电偶极 / 缝隙耦合 / 螺旋 / 阵列 …)。
2. 读 `knowledge/INDEX.md` → 对应的 `knowledge/<type>.md` 和 `knowledge/_general.md`。
   `_optimization.md`(扫参/调匹配)和 `_solving.md`(长求解、求解变慢/失败/结果可疑)做到那一步再读。
3. 改结构/换拓扑/加一层之前,先把关键**电尺寸比值**(臂长/λ、层间距/λ、升角)算出来和参考对比
   (有 `papers/INDEX.md` 就查它,没有就用手头论文或 `design/` 卡片的归一化常数)。比的是电尺寸比值不是毫米数。
   一轮仿真几十分钟,查一次一分钟。
4. 没有对应类型文件 = 第一次做这类,正常进行,收工时新建。

## 收工先记:`knowledge/`
复杂任务做完、或中途卡过壳/绕过坑之后,把**非显然、换一篇同类但结构不同的论文还用得上**的东西,
追加进 `knowledge/<type>.md`(没有就新建,并在 `INDEX.md` 加一行)。先扫一眼有没有类似条目,有就更新,别堆重复。

```
## <一句话标题>
- 现象:看到什么
- 原因:为什么
- 解法:怎么做 / 怎么绕过
- 适用:(可选)什么条件下成立
```

- ✅ 记:工作机理、通用建模陷阱、哪个自由度控什么(谐振/匹配/带宽/方向图)、馈电与层叠的套路、收敛与匹配经验、文献符号易混点
- ❌ 不记:某一款的具体结构与尺寸、某个工程的实测数字当规则、一次性手误、工具 bug(那进代码)

## 收工先记:`design/` 卡片
只在**设计仿真达标**(`check_design_targets` 的 `all_pass`)**且用户确认要沉淀**之后录。
没有该类卡就复制 `design/_TEMPLATE.md` 新建,frontmatter 填齐(供 `search_designs` 检索),并在 `design/INDEX.md` 加指针。

录什么有优先级:**闭式公式**(一套服务任意 f₀/εr)> **λ₀ 归一化常数**(注明对应 εr)> 报告性能与出处(DOI)。
**某一款的绝对毫米尺寸不入库**——换个频率或 εr 就作废,留着只会误导后来的检索。
文献来源的设计同样先建模仿真达标再录,不许照抄论文数字入库。
