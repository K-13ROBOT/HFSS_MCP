# 流程:调参(灵敏度 → 扫参 → 公差 → 优化)

> 指标不达标时怎么调。**顺序有讲究**:先用灵敏度问"该动哪个变量",
> 再扫参;达标之后、投板之前才做公差与良率。
> **退出条件(可数,别靠判断)**:连续两轮扫参后 `check_design_targets` 的
> `failed_metrics` 没少一项 → 停,去 [diagnose-current.md](diagnose-current.md) 看机理。
> 选不出该动哪个变量 → 先做本页的灵敏度分析。
> 「方向是对的、只是力度不够」是最贵的自我说服,每信一次就是一整轮机时。
>
> **配套经验:[`../knowledge/_optimization.md`](../knowledge/_optimization.md)** —— 本卡讲步骤,
> 那边讲判断(参扫 vs 手工逐点怎么选、频率旋钮的线性缩放律、别追小于仿真重复性的余量)。

## 第零步:调参之前先做一次网格校准(硬规则,不许跳)

**调参的每一轮都建立在"当前网格算得准"这个前提上。前提没验过,后面所有轮次可能全是假的。**

做法:**拿当前设计(基准点),换一个明显更严的设置重解一次**,比对关键指标。

**先估时长再动手**:校准本身就是一次完整求解,按 30 分钟单轮上限估。
**优先收紧判据,慎用网格长度加密** —— 两者代价差一个量级:
- ✅ **首选:收紧判据**。`create_setup` 里同时改两个:
  - `max_delta_s` 降一档(如 0.02 → 0.01),并加大 `max_passes`
  - **`min_converged_passes=2`(要求连续两遍满足)—— 这条不能省。**
    只降 ΔS 不改它,网格还粗时恰好一遍满足照样判收敛,等于没收紧。
    (实测假收敛:ΔS 0.03 + 只要求 1 遍,第 5 遍、39k 网格就判了收敛)
- ⚠️ **慎用:`assign_mesh_length` 加密**。实测 0.12mm 加密让网格从 133k 涨到 499k,
  **一轮跑了两小时**。只在收紧判据之后指标仍在跳、且能定位到具体窄缝时才用,局部加,别全局加。

比对:
- **比的是关键指标的偏移**,不是 S 曲线整体长得像不像:谐振频率、频段边缘、匹配深度
- **判据:频段边缘/谐振频率偏移 < 1%** 才算当前设置够用
- 两次求解的 `analyze` 返回值里都带着 `convergence`(轮数、末轮单元数、
  `consec_passes_required`)—— 先确认更严的那次**真的更严**(单元数确实涨了、确实连续两遍),
  别拿两次差不多的网格互相印证

两种结果,两种走法:
- **偏移 < 1%** → 当前网格够用,可以放心用它调参(而且证明了不必花大网格的钱)
- **偏移 ≥ 1%** → **当前网格下调出来的东西不可信**,先把网格定下来再调。
  否则会出现"调到达标,一加密网格又不达标"——白调一整轮

实测这一步是最值钱的一步:同一结构 499k 单元对 133k 单元的对比,**一次就证明了 133k 够用,
同时证明了此前放宽判据跑出来的那批数据是假的**。没做这一步之前,那批假数据已经指导了好几轮调参。

`analyze` 的返回值里带着收敛摘要(`convergence`:轮数、末轮单元数、末轮 ΔS、是否收敛)——
**`converged: false` 时连校准都不用做,直接加大 max_passes 重解**,那组结果本身就不可信。

## 多谐振结构:第一次不达标就先看电流,别等两轮

双频、宽带多模、寄生加载这类结构,**第一次不达标就先去 `diagnose-current.md`**,
在每个谐振点各取一次电流,搞清楚**"谁负责哪个谐振"**,再选旋钮。

理由:多谐振结构里一个尺寸往往同时动好几个谐振,不知道谁管谁就去扫,
大概率动错旋钮(调了 A 想移低频,实际 A 管的是高频)。
单谐振结构的退出条件是"连续两轮未达标项没少就停";**多谐振结构把门槛提到第一轮** ——
诊断一次的代价远小于在错的旋钮上扫两轮。

## 扫之前先问一句:该动哪个变量(灵敏度分析)
候选变量超过一个、又拿不准该扫谁时,**先 `create_sensitivity` + `run_sensitivity`**,
它在当前工作点附近算出**每个变量对指标的偏导**,`get_sensitivity_result` 给排序和相对权重。

- **`relative` 远小于 1 的变量,扫了也是白扫** —— 直接固定,把机时花在 dominant 那个上
- 返回的 `verdict` 会提示两种情形:一家独大(只扫它)/ 两个量级相当(单独扫任一个都会被
  另一个带偏,得二维扫或先固定其一)
- **`nonlinearity` 大**(|二阶导/一阶导|)说明工作点附近非线性强,`_optimization.md` 里
  "频率类旋钮线性缩放律很准"那条在这种情况下不成立,别线性外推估步长,缩小扫描范围

为什么值得先花这一步:灵敏度是**工作点附近取少量点求梯度**,比笛卡尔积的粗扫便宜得多;
而且它给的是**当前这个结构**的实测偏导 —— 一个尺寸同时影响多个指标时,耦合关系直接看得见,
不用去猜卡片里的经验映射适不适用于这一款。

**不用的场合**:只有一个候选变量(没得选)、或者已经知道该动谁(卡片写明了、或上轮扫过)。

## 扫参本身
1. 变量必须先 `set_variable`
2. `create_parametric_sweep`:**要远场指标必须传 `save_fields=True`**;只看 S 参数保留默认 false 省盘。返回值回显 `save_fields` 确认已生效;被扫变量原是表达式时会带 `pinned_to_numeric`(工具自动钉成纯数值,正常现象)
3. `run_parametric_sweep`(阻塞,组合数多很久)
4. `get_parametric_results` / `get_parametric_gain` / ... 取指标表

参数扫描共用网格,比"循环改变量 + 多次 analyze"快得多。组合数=各变量取值数乘积,别盲目大范围。
get_parametric_* 异常(只 1 个 variation、字段全空)时先让用户排查,**不要退化成手动循环**(会丢已跑结果)。

⚠️ **参扫按 ID 引用求解 setup,不是按名字**:`delete_setup` 之后(哪怕马上同名重建)原参扫就成了孤儿——
再跑报 `com_error(-2147024357)`,且 `validate_design` 会一直报 `<参扫名> - Need to include at least one simulation setup`。
用 **`delete_parametric`** 清掉孤儿参扫(约定同 `delete_setup`:`confirm=true` 才真删、不传 names 只回显清单)。
所以**要换 setup 就连参扫一起重建**,别指望同名接上。

## 公差与良率:这个设计投产能做出来吗(统计分析)
**什么时候做**:**设计已经达标之后**,交付/投板之前问一句"按板厂的公差,批量下来有多少合格"。
仿真漂亮但批量一半不合格,就是没做过这一步。调参过程中不要做 —— 那时候设计还在变,算了也作废。

`create_statistical` + `run_statistical` + `get_statistical_result`:给变量加公差分布,
蒙特卡洛采样跑 N 次,得到指标的分布;给了 `spec_value` 还会直接算**良率**。

**公差怎么填**:板厂给的 ±公差通常是 **3σ**,所以 ±0.3mm 对应 `std_dev='0.1mm'`。
加工公差用 `Gaussian`;要估最坏情况用 `Uniform`。

**⚠️ 代价是 trials 次完整求解** —— 50 次就是 50 轮 analyze,动辄几十分钟到几小时。
**必须先预告耗时等用户确认**。先用 10~20 次看趋势,要可信的良率数字才上 50+
(工具会在 n<20 时提示置信区间有多宽)。

**结果怎么用**:
- 关键不是良率那个数,是 **`spread` 和 `std_dev`** —— 它们说明这个设计对公差有多敏感
- **良率低时,配合 `tuning.md` 的灵敏度分析定位是哪个变量在拖后腿**,然后二选一:
  找板厂把那一项卡紧(贵),或者改设计让它对该变量不敏感(更值)
- 公差分析只在**达标设计**上做才有意义;对一个本来就不达标的设计算良率,
  得到的 0% 不是公差问题

## 自动优化(用户说"优化/调到目标/找最优")
两条路,先选对:
- **HFSS 内置优化器**(`create_optimization` → `run_optimization` → `get_optimization_result`):求解器自己梯度/遗传迭代逼近**单一目标**。**首选**于:平滑问题、1-3 个变量、向明确目标精修(如把 S11 压到 ≤-15dB)。`get_optimization_result` 直接给最优变量值(HFSS 写回 design)。注意:**单目标**;多目标(S11+增益+HPBW 同时)暂用下面的手动扫参。
- **手动三阶段扫参**(你充当算法):适合**粗看整个设计空间**、多目标权衡、或想看完整扫描曲线时。

**开扫/开优化前必做**:显式列出 metric + target + 方向(多目标列清楚等用户确认权衡)。

手动三阶段:
- 阶段 1 粗扫定位:大范围 3-5 点(name `*_coarse`)
- 阶段 2 细扫精修:最优区间附近 7-11 点(name `*_fine`)
- 阶段 3 单点验证:`set_variable` 落最佳值,`analyze` + `get_*` 复核

工程纪律:每开 parametric 前估时间(超 5 分钟先告诉用户等确认);阶段 1→2 之间必须中途汇报;
每阶段新 name;多变量先单变量看敏感性再联合细扫,不要直接 5×5 笛卡尔积;报达标给具体数值
("目标 X,实测 Y,偏差 Z dB");卡住时指出哪个变量到边界,**不要无限扩范围撞运气**。
