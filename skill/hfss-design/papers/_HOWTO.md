# 原文库读法(通用框架)

> 本文件是**通用方法**,随 install.py 分发;每篇论文的「章节→页 / 图表→页」索引在同目录
> `INDEX.md` 里,那是个人资料,不随分发走。

**为什么有这个目录**：`design/` 的卡片是从这些原文蒸馏来的，一行一个变体，**细节损失很大**。
实战中反复出现的情况是：照卡片那一行反推拓扑 → 猜错 → 建歪 → 浪费几轮求解，最后还是要回来看原图。

> **规矩：卡片只用来"选型"（哪个变体适合我的指标），一旦决定要建某个变体，
> 先按 `INDEX.md` 里那篇的「图/表→页」跳到原文的那张图和那张尺寸表，看完再动手。** 别从卡片的一行摘要反推几何。

## 怎么读 PDF 里的图

环境里默认没有 PDF 渲染器（Read 工具对 PDF 会报 `pdftoppm is not installed`）。已验证可用的办法：

```bash
# 一次性装（用跑 MCP server 的那个 python，保证和它同环境）
python -m pip install pymupdf

# 渲染某一页成 PNG，再用 Read 工具看
python -c "
import pymupdf
d = pymupdf.open('papers/xxx.pdf')
d[24].get_pixmap(dpi=200).save('out.png')   # 注意：索引从 0 开始，d[24] 是第 25 页
"
```
- **要看图里的细节标注**（尺寸符号指向哪条边、哪段折向哪），用 `clip=pymupdf.Rect(...)` 裁出那块再上 `dpi=600`，否则标注糊成一团。
  用相对坐标写裁剪框好复用（`r = d[n].rect`，框取页面右上角那类）：
  `d[n].get_pixmap(dpi=600, clip=pymupdf.Rect(r.width*0.52, r.height*0.06, r.width*0.98, r.height*0.24))`
  **值得这么做的典型场景**：馈电结构的分段标注、折叠件的朝向、开槽的起止边——
  这类信息**常常只画在图上、全篇正文一个字都没有**，裁不清楚就等于没读到。
- **正文和尺寸表用 `pdftotext -layout -f N -l N`** 抽，比渲染快得多。
  ⚠️ 多列的尺寸表经常被抽乱行（数值和参数名对不上）——**表被抽乱时以"λ₀ 归一化那一列"为准**，
  或直接渲染那一页用眼睛核对。
  ⚠️ 更阴的情况：一张表里**混了两个设计**的数值（mm 列与 λ₀ 列互相矛盾）。发现两列换算不上就别硬用，
  回图上核对是哪一套。


## 新增文献时

1. 把 PDF 放进本目录（`papers/`）；
2. 用 `pymupdf` 扫一遍，把「章节→页」「图/表→页」两张表登记进同目录的 `INDEX.md`（方法见上）；
3. 如果它是某张 `design/` 卡片的来源，**在那张卡片里回指 `INDEX.md` 的对应行**；
4. 精读时抽出的**可复用结论**（哪个尺寸控什么、基板厚度容许区间、馈点阻抗这类）
   写进 `knowledge/<type>.md`；**具体某一款的绝对尺寸不入库**（见 SKILL.md §0.3）。
