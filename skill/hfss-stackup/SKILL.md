# PCB 叠层表 → HFSS 多层板(板级/工艺,跨天线类型)

**何时读**:用户丢来一份板厂叠层表(StackUp Report,xlsx/csv),要求在 HFSS 里建出这块板——
不管上面最后放的是天线、走线还是什么都不放。**建天线时用户指定了真实生产叠层,也读这篇。**

核心难点**不在 HFSS 操作,在读懂叠层表**:同一份报告里藏着好几条不成文的行业约定,
读错一条整块板厚度就错,而且错得很隐蔽(层数、层序看着都对)。

流程:**dump 表格 → 按规则解析 → 厚度自校验 → 出层表让用户确认 → 建模 → bbox 自检 → setup**。

与 `hfss-design` skill §3.5 的关系:那边是**文献复现**时自己编层叠的约定(层少、自己定厚度);
本篇是**厂商给定**叠层的还原(层多、厚度不可改、必须和总厚对上)。z 约定一致(底面 z=0,+z 向上)。

---

## 1. Dump 原始表格(别用 Read 直接看 xlsx)

xlsx 是二进制,`Read` 读不出来。一次性把整张表打成文本再自己判读:

```bash
python -c "
import openpyxl
wb=openpyxl.load_workbook(r'<路径>',data_only=True)
ws=wb[wb.sheetnames[0]]
for r in ws.iter_rows(max_row=ws.max_row,max_col=ws.max_column):
    print(r[0].row,'|'.join('' if c.value is None else str(c.value) for c in r))
"
```

- `data_only=True` 必须加,否则公式单元格返回公式字符串而不是值。
- 顺手 dump 一次 `ws.merged_cells.ranges`:**是不是合并单元格,决定了空白格怎么解释**(见 §2.4)。
- 表头行不一定在第 1 行,前面常有 Job Name / Finish Board Thickness 等元信息行。
  **`Finish Board Thickness` 是最重要的一行——它是你后面自校验的标尺,先抄下来。**

> **不要写解析脚本当交付物。** dump 完你自己按下面规则读、自己算 z,规则和判断留在对话里。
> 脚本会把"这份表长这样"写死,换一家板厂就废;你的判读能力才是可迁移的。

## 2. 解析规则(踩过的坑都在这)

典型列:`Layer Index | Stackup Buildup | PP Name And RC | Dielectric Thickness(mm) | Finish Cu Thk(oz) | Material Family | Copper Rate(%)`

### 2.1 行的两种类型看第一列
- 第一列是 `L<n>` / `D<n>` → **铜层行**,厚度在 `Finish Cu Thk` 列(oz)。
- 第一列是 `Core` 或**空白** → **介质行**,厚度在 `Dielectric Thickness` 列(mm)。

行序就是层序,**表格从上到下 = 板子从顶到底**。

### 2.2 `D<n>` 是"占号不占铜"的层 —— 必须跳过
`D14`、`D16` 这种行,`Stackup Buildup` 和 `Finish Cu Thk` 全空。它是**保留的层号但整层没有铜**
(设计上留了序号,实际全蚀刻掉)。**建模时不要为它建实体**,厚度按 0 计。
判据:`L` 开头且 Cu 列非空 = 有铜;`D` 开头或 Cu 列空 = 无铜。

⚠️ 直接影响层数:一块"L23"的板,真实铜层数 = 23 − D 层数。别照着最大层号建 23 层铜。

### 2.3 oz → mm,以及 "+ Plating"
- `1 oz = 35 µm = 0.035 mm`,按倍数线性换算(0.5oz=17.5µm、2oz=70µm)。
- `0.5oz + Plating` = 基铜 + 电镀铜。**电镀增量表里从来不给**,典型 ~18–20 µm。
  取一个待定值 `T_PLATE`,用 §3 的总厚校验反解它——校验能对上,说明取对了。

### 2.4 连续多行同名 PP:厚度是"这一组的总厚",不是每片
最容易错的一条。经常看到:

```
|PP|PP(1035)RC76|0.108||SJ7036N|
|PP|PP(1035)RC76|||SJ7036N|      <- 厚度空白
```

这是**两张半固化片压在一起**,`0.108` 是**两张加起来的总厚**,不是每张 0.108。
处理:厚度空白的介质行**并入上一条介质行**(片数 +1,厚度不变),合成**一个** HFSS 实体。

⚠️ 不要因为"没合并单元格"就以为空白是漏填 —— §1 里 dump merged_cells 就是为了确认这点。
判对判错靠 §3 的总厚校验,差一倍立刻看得出来。

## 3. 总厚自校验 —— 建模前必做,这是唯一的客观标尺

把所有层厚加起来,和元信息里的 `Finish Board Thickness` 比:

```
Σ(介质厚) + Σ(铜厚) ≟ Finish Board Thickness
```

- **对得上(误差 < 1%)** → §2.2/2.3/2.4 三条规则这次都判对了,放心往下走。
- **差了大约一组 PP 的厚度** → §2.4 判反了(把总厚当成了每片)。
- **差几十 µm 且随镀铜层数变化** → `T_PLATE` 取错,用差值 ÷ 镀铜层数反解。
- **差整层铜** → D 层当成有铜了。

> 这一步是整个流程的地基。**不核对总厚就开始建模 = 建到一半才发现层表是错的。**

## 4. 出层表 → 定 z → 让用户确认

自校验通过后,按行序累加算出每层的 `z_bot / z_top`。约定:
- **z=0 放在最底层(L 最大那层)的底面,+z 向上**,这样 L1 在最顶 —— 和看板子的直觉一致。
- xy:板做成矩形试样,**以原点为中心**(`position=['-bw/2','-bl/2',z_bot]`),
  后面加走线/过孔时坐标好算。

然后**把层表输出给用户过目**(序号/类型/名字/材料/厚度/z 范围),同时**明确列出你的假设**:
- 用了什么 Dk/Df(叠层表**只给材料牌号不给电参数**,你必须查或假设 → 见 §5)
- `T_PLATE` 取值
- 试样 xy 尺寸和频段(用户没指定时你自己定,但要说出来)

用户扫一眼就知道你哪条读反了,比你自己反推可靠。

## 5. 材料

- **介质**:叠层表只给 `Material Family`(如 `SJ7036N`),**不给 εr/tanδ**。
  用 `create_material` 按牌号数据手册的值建,**别拿库里的 FR4_epoxy 将就**(εr 4.4 vs 高速板 ~3.3,
  阻抗和延迟会系统性偏)。查不到就取一个合理值并**在报告里明确标为假设**,让用户替换。
- 严格说 Core 和 PP 树脂含量不同、Dk 略有差异。表里只给一个牌号时用**同一个材料**,
  并告诉用户"要分开就给我 Core/PP 各自的 Dk"。
- **铜**:直接用 HFSS 内置 `copper`,不要用 PerfectE —— 建的是实体铜箔,有厚度,
  要算导体损耗时 `copper` 才对。

## 6. 建模(hfss-agent MCP)

### 6.1 会话
`open_desktop` → `new_project` → **`new_design`**(别漏 `new_design`,见 `_general.md`)。
叠层做信号完整性一般用 `solution_type='Terminal'`。

### 6.2 全参数化 —— 几何里不许出现任何字面量数字

**这是硬要求,不是可选项。** z 坐标算成 `'3.3639mm'` 直接填进 `create_box` 看起来省事,
但那是**死模型**:改一层厚度,上面 20 层不会动,整摞要手工重算重建。叠层模型的价值
恰恰在于"改一个厚度看阻抗怎么变",写死等于白建。

三层变量,自底向上:

**① 基元**(所有铜厚都从这两个派生)
```
t_oz      = 0.035mm     1oz 铜箔厚
t_plating = 0.0187mm    电镀增量(见 §2.3,由总厚校验反解)
board_w / board_l       试样 xy 尺寸
```

**② 每层厚度** —— 表达式**直接照抄叠层表的 oz 写法**,一眼能和原表对上:
```
t_cu_L1  = 0.5*t_oz+t_plating    <- 表里写 "0.5oz + Plating"
t_cu_L3  = 2*t_oz                <- 表里写 "2oz"
t_cu_L8  = 1*t_oz
```
介质**按"夹在哪两层铜之间"命名**,不要用行号:
```
t_core_L1_L2      L1 与 L2 之间那张 Core
t_pp_L12_L13      L12 与 L13 之间那组 PP
t_core_L13_D14    D 层也参与命名(它占层号,是真实的层界)
```
> 命名要能**脱离表格自解释**。`t_pp_L12_L13` 谁都知道是什么;`DE24` 三天后你自己都不认识。

**③ 每层 z(底面)** —— 链式引用下面一层,这是"改一处、整摞自动重排"的机制所在:
```
z_L23          = 0mm                              <- 唯一的锚点,放最底层
z_core_D22_L23 = z_L23 + t_cu_L23
z_pp_L21_D22   = z_core_D22_L23 + t_core_D22_L23
...一路累加到...
z_L1           = z_core_L1_L2 + t_core_L1_L2
board_thickness = z_L1 + t_cu_L1                  <- 派生只读量,拿来核对总厚
```
- **z 变量名 = 对象名**(`z_pp_L2_L3` ↔ 对象 `PP_L2_L3`),对得上才好查。
- **`board_thickness` 必须建**:它让"总厚 3.4mm"这个校验**活在模型里**,
  以后改任何一层,在 HFSS 里看一眼这个变量就知道还合不合规格。
- 变量数量会到 80~90 个(23 层板)。**别嫌多** —— 每个都是一行、名字自解释,
  比 41 个散落的字面量好维护一个数量级。

⚠️ **`set_variable` 有先后依赖**:被引用的变量必须先存在。
z 变量**严格自底向上**逐个定义,一条消息里并发发 10 个是安全的(server 按序执行),
但**跨批次时下一批的第一个必须依赖上一批已完成的**。

⚠️ **MCP 没有 delete_variable**。变量名一旦建错(或换了命名方案),只能在 HFSS 里
手工删(Project > Design Properties)。所以**命名方案要一次定好再开建**。

### 6.3 建实体
每层一个 `create_box`,`position` 和 `size` **全部是变量名**:
```
position = ['-board_w/2', '-board_l/2', 'z_pp_L2_L3']
size     = ['board_w',    'board_l',    't_pp_L2_L3']
```
- 对象命名和变量对齐:铜 `L1_Cu`/`L13_Cu`,介质 `Core_L1_L2`/`PP_L12_L13`。
  (代价是模型树按字母排会把 `L10_Cu` 排在 `L2_Cu` 前面 —— **可读性优先,认了**。)
- 跳过所有 D 层(§2.2),但它们的层号仍出现在相邻介质的名字里。
- **`create_box` 之间无依赖,一条消息里并发发 10 个**,41 层分 4 批。

### 6.4 验证参数化真的生效(建完必做一次)
建完别急着报完成 —— **改一个基元变量,看整摞动不动**:
```
把 t_plating 临时改成 0.03mm
→ 8 个镀铜层各 +0.0113mm → board_thickness 应从 3.4001 变成 3.4905
→ 用 get_object_bbox 查 L1_Cu:zmax 确实变了,L23_Cu 的 zmin 仍是 0(锚点不动)
→ 改回原值,再查一次确认复原
```
这一步能同时抓出两种错:z 填了字面量(整摞纹丝不动)、
链式引用接错层(某几层动了、某几层没动)。

## 7. 几何自检:`get_object_bbox` 不传名,一次取全部

拿到全部 bbox 后,**逐对检查相邻层 `上层.zmin == 下层.zmax`**(容差 1e-9)。
一条链走下来:无缝隙、无重叠、首尾 z 跨度 == 总厚。层数多的时候人眼核对不现实,
把 bbox 抄进一个临时 python 片段跑一遍比较靠谱。

同时确认:铜层数 == 有铜的 L 层数,介质数 == 合并后的介质组数。

## 8. Setup / 扫频:纯叠层没有端口

`create_setup` 正常;扫频必须 `sweep_type='Discrete'` + `save_fields=True`
——原因见 `_general.md`「无端口设计的扫频」。点数别贪多(存场很占盘),20 来个点够。

> 端口/激励要等有了实际结构(走线、过孔、差分对)才加。**只有叠层时不要硬塞端口**,
> 也不要跑 `analyze` —— 没激励算不出有意义的东西。这时 `validate_design` 报缺激励是正常的。

## 9. 交付

- 工程存进 `HFSS_PROJECTS_DIR`(`save_project`)。
- 层表导一份 CSV 到 `HFSS_EXPORTS_DIR`,当作"表格 → 模型"的可追溯记录。
- 变量表用 `list_variables` 导一份,和层表 CSV 放一起。
- 回复里**把假设单独列出来**(Dk/Df、T_PLATE、试样尺寸、频段),这些是后面出结果时最容易背锅的地方。
