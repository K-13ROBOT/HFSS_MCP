# 天线文献检索与提炼

补的是 `hfss-design` §10 正向设计闭环第 1 步那个死胡同:**卡片库没有匹配拓扑时怎么办**。
本 skill 的交付物是**「结构理解表 + 起手尺寸」交用户确认**,不是卡片 —— 卡片是整条流程走完、
仿真达标、用户点头之后才录的(见 §5)。

## 0. 先查本地库 —— 硬门槛,不许跳

**任何情况下先调 `search_designs`**(传 frequency_ghz / polarization / topology / min_gain_dbi),
命中就用 `read_design_card` 取正文,直接走 `hfss-design` §10 第 2 步缩放建模,**不要联网**。
只有确认库里没有可用拓扑,才进本 skill 后续步骤。

理由:库里的卡是自己验证过的,可信度和可用性都高于任何论文;联网检索慢且贵。

## 1. 指标 → 拓扑候选 → 检索式

先把用户指标翻成**拓扑候选**,再翻成**英文检索词**。中文检索天线文献基本无效,检索式一律用英文。

**指标 → 拓扑的常用映射**(候选,不是唯一解):

| 指标特征 | 优先考虑的拓扑 | 检索关键词 |
|---|---|---|
| 窄带、低剖面、低成本 | 矩形/圆形微带贴片 | `microstrip patch antenna` |
| 圆极化(单馈) | 切角/开槽贴片 | `single-fed circularly polarized patch`, `truncated corner` |
| 圆极化(宽轴比带宽) | 双馈+90°电桥、序列旋转 | `dual-fed CP antenna`, `sequential rotation` |
| 宽带(>30%) | 磁电偶极子、E 型/U 型开槽贴片、堆叠贴片 | `magneto-electric dipole`, `E-shaped patch`, `stacked patch` |
| 高增益(单元) | 缝隙耦合叠层、SIW、介质谐振 | `aperture-coupled stacked`, `SIW antenna`, `dielectric resonator antenna` |
| 高增益(阵列) | 微带阵 + 馈电网络 | `microstrip array`, `series-fed`, `corporate feed` |
| 宽波束/半球覆盖 | 单极子、PIFA、缝隙 | `monopole`, `PIFA`, `slot antenna` |
| 毫米波 | SIW、贴片阵、透镜 | `mmWave antenna`, `substrate integrated waveguide` |
| 双频/多频 | 开槽、寄生单元、分形 | `dual-band patch`, `parasitic element` |

**检索式模板**(按需组合,别一次堆太多词,先宽后窄):
```
<拓扑关键词> AND (<频段词>) AND (<性能约束>)
如: "magneto-electric dipole" AND "5G" AND "wideband"
    "circularly polarized patch" AND "axial ratio bandwidth" AND "single feed"
```
频段词用**应用名**往往比数字好使(`sub-6 GHz` / `5G n78` / `WLAN 2.4 GHz` / `Ka-band`),
因为论文标题里写应用名的比写具体频率的多。

## 2. 检索源与分工

**我能自主做的**(有联网工具时):
- `WebSearch` 找综述和公开可读的论文,快速摸清这类天线有哪些主流做法
- IEEE Xplore 的**检索结果页**通常可读(标题/摘要/DOI),据此出候选清单
- arXiv(eess.SP 有部分天线文章)、MDPI 系期刊、开放获取论文可直接读全文

**必须用户做的**:**下载 IEEE / 付费期刊的 PDF**。我的网页抓取不带用户的登录态和学校 IP,
拿回来只会是登录页。所以流程是:**我给候选清单和链接 → 用户下载 → 把 PDF 路径告诉我**。

> **别做批量下载。** 出版商对高频抓取有风控,触发会封整个机构的 IP 段,代价由全校承担。
> 每轮候选控制在 3~5 篇,选定 1~2 篇精读即可。

**没有联网工具时**(换了 MCP 客户端 / 无网):直接请用户提供论文 PDF 或粘贴关键段落,
跳到 §3 精读。本 skill 的提炼纪律不依赖联网。

## 3. 候选筛选:能不能用,看这五道门

拿到候选清单后**先筛再读**,别一上来精读五篇。逐篇过这五道:

1. **拓扑/极化对不对** —— 线极化的卡拿来做 CP 是白费;单馈 CP 和双馈 CP 的设计自由度完全不同。
2. **频段能不能缩放过来** —— 见下面「可缩放性」,这是最容易想当然的一道。
3. **基板 εr 差多少** —— εr 不同不能直接搬尺寸(见下)。差得远且论文没给闭式公式,这篇的迁移价值就低。
4. **报告性能留没留裕量** —— 论文报的增益/带宽应当**优于**目标,不能刚好卡线。复现结果通常比论文差
   (加工/连接器/地板尺寸/测试环境),没有裕量大概率不达标。另外看清是**仿真值还是实测值**。
5. **★ 这个结构我们建得出来吗** —— 用 `hfss-design` 现有工具(box/rect/cylinder/polyline
   + 布尔 + 变换)能不能搭。多层盲埋孔、复杂曲面、异形超表面单元、需要精细工艺的结构,
   即使论文再好也先跳过。**这道门是本项目特有的,别忘了过。**

### 可缩放性:什么能跟着频率走,什么不能

- **平面尺寸 ∝ 1/f** —— 成立的前提是 **εr 不变、且基板厚度 h 也按同比例缩**。只缩平面不缩 h,
  电厚度 h/λ₀ 就变了,而 h/λ₀ 是**带宽的主控参数** —— 缩到高频带宽会变宽但可能激起表面波/高次模,
  放到低频则带宽塌掉。**换频率必须连 h 一起检查。**
- **εr 变了不能搬尺寸** —— εeff、λg、边缘缩短量 ΔL、输入阻抗全跟着变。有闭式公式的(如矩形贴片)
  重算即可;没有闭式、只给了某个 εr 下归一化常数的,**换 εr 就不通用**——这正是卡片 frontmatter 里
  `eps_r: any`(闭式型)和具体数值(经验型)的区别。
- **不随波长缩放的绝对尺寸会成为瓶颈** —— 金属层厚、加工最小线宽/间隙、探针与同轴内导体直径、
  连接器尺寸。论文在 2.4 GHz 用 0.5mm 间隙,缩到 28 GHz 就是 0.043mm,做不出来也仿不准。
- **损耗不能照搬** —— tanδ 和导体损耗随频率恶化,同一基板在高频的效率/增益比论文低。

## 4. 选定之后:交回原文库流程精读

**本 skill 到「筛出值得读的 1~2 篇」为止,不自己另立一套读 PDF 的方法。**

选定后走 `hfss-design` skill 的 **`papers/` 原文库**流程:PDF 放进 `papers/`,按
`papers/_HOWTO.md` 的方法渲染/抽取,并把「章节→页」「图表→页」两张表登记进 `papers/INDEX.md`。
那份 HOWTO 是实战验证过的(**`Read` 工具对 PDF 依赖 `pdftoppm`,很多环境里没有;
已验证可用的是 pymupdf 渲染成 PNG 再看图、`pdftotext -layout` 抽正文和表格**),
照它做,别在这里重造。

登记完再回本 skill §5 出确认表。**跳过登记的代价**是:下次要复核某个尺寸的来源,
又得把整篇 PDF 重读一遍。

**抽取纪律**(与 `hfss-design` §0 读图纪律同源,必须遵守):
- **数字只从参数表 / 正文文字里抽,绝不在结构图上量** —— 图有透视、引线密集,量必错。
- **抽不到就标 `unknown`,不许推测、不许"看着差不多"填一个** —— 编的数字比没有更糟,
  它会一路传到建模,最后你以为在复现论文,其实在复现自己的臆想。
- **结构图只用来判拓扑** —— 谁连谁、谁压谁、层叠顺序、馈线走向、开槽位置。
- **多列尺寸表被抽乱是常态**(数值与参数名错行)——以 λ₀ 归一化那一列为准,或渲染该页用眼核对。
- **记住出处** —— DOI/arXiv ID + 参数表在第几页,后面每个数字都要可回溯。

## 5. 交付物:结构理解表,交用户确认

**这是本 skill 的终点,不是卡片。** 精读完输出下面三样,请用户确认/纠正后再进建模:

1. **结构理解表** —— 有哪几个部件、材料、谁搭谁、馈电怎么进去。拓扑有歧义就在这里停下来问,
   别自己拍板往下建。
2. **层叠表** —— 每层的 z 起止(按 `hfss-design` §3.5 的坐标约定表述,方便直接建模)。
3. **起手尺寸表** —— 论文给的绝对尺寸 + 缩放到目标频率/基板后的值,逐项标出处页码,未知项标 `unknown`。

> **起手尺寸是一次性用品**:它服务于本次建模,**不入库**。换个频率或基板它就作废,
> 留在库里只会误导后来的检索。

确认无误后,交回 `hfss-design` §10 第 2 步:`set_variable` 落变量 → 建模 → `analyze`
→ `check_design_targets` 对标 → 不达标走扫参/优化。

## 6. 收工沉淀:达标之后,且用户点头,才录库

**只有当设计真的仿到达标(`check_design_targets` 的 `all_pass`)、并且用户确认要沉淀时**,
才把这次的收获录进库。**录的是公式和经验,不是那张尺寸表**:

| 录什么 | 去哪 | 判据 |
|---|---|---|
| 闭式公式、λ₀ 归一化常数、设计自由度(哪个尺寸控哪个指标) | `design/<type>.md` | 换个频率/εr 还用得上 |
| 机理、建模陷阱、调试时踩的坑 | `knowledge/<type>.md` | 换一篇同类但结构不同的论文还用得上 |
| 论文那一款的绝对毫米尺寸 | **哪都不去** | 换频率就作废,留着误导 |

具体格式走 `hfss-design` §0.2 / §0.3 的规矩:`design/` 复制 `_TEMPLATE.md` 建卡、
frontmatter 填齐供 `search_designs` 检索、`source:` 写清 DOI;`knowledge/` 只记类级别的通用经验。
两个库的目录位置用 `list_design_cards` 返回的 `dir` 字段定位,**别硬编码路径**
(它会自动解析 `HFSS_DESIGN_DIR` → `~/.claude/skills/...` → bundle 内三个候选)。

论文 PDF 放 `hfss-design` skill 的 `papers/` 目录(版权原因不入 git),并在 `papers/INDEX.md` 登记;
卡片的 `source:` 写 DOI 并回指 `papers/INDEX.md` 的对应行,以后要翻推导还能找到原文和页码。

## 7. 常见坑

- **一上来就联网** —— §0 那道门必须先过,库里有就别去外面找。
- **精读太多篇** —— 筛选是廉价的,精读是昂贵的。五道门筛完选 1~2 篇,不要五篇都读。
- **把摘要里的性能当设计依据** —— 摘要只够判"值不值得读",尺寸和自由度必须看正文参数表。
- **拿到尺寸就急着建模** —— §5 的确认表是给用户纠错的机会,复杂结构尤其要停一下。
- **达标前就写卡片** —— 卡片库的价值全在"里面的数字都验证过";写没验的进去,库就废了。
- **把绝对尺寸当经验录进去** —— 见 §6 表格第三行。
